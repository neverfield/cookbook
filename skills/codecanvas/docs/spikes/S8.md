## 1. Question

Can codecanvas run a headless `claude -p --output-format stream-json` coding agent inside an isolated `git clone --shared` agent clone such that:

1. Every out-of-clone filesystem write — via **direct Bash**, **Node scripts**, **npm `postinstall` hooks**, and **`git` writes targeting the parent `.git` / `core.hooksPath` / worktree admin dir** — is blocked at the OS kernel level?
2. A Claude Code `PreToolUse` hook enforces clone-boundary path containment (including symlinks and clone `.git/` admin files) as defense-in-depth without blocking legitimate in-clone reads, writes, or `git commit`s?
3. Platforms lacking a working OS sandbox **fail closed** (no weaker fallback)?

### Key Finding: Why Daemon-Owned Linux Sandboxing Matters

`ARCHITECTURE-V2` §10.2 originally assumed relying on Claude Code's built-in OS sandbox alone. On Linux, Claude Code's built-in sandbox depends on `bwrap` (bubblewrap), which is **not installed on this VM** and is also frequently blocked on Ubuntu 24.04+ hosts where `kernel.apparmor_restrict_unprivileged_userns=1` or container seccomp policies disallow unprivileged user namespaces.

Testing on this VM revealed a significantly stronger, more portable Linux design owned directly by the codecanvas daemon:

| Linux Backend | Mechanism | Requires `bwrap` / userns? | Startup Overhead (10 runs) | Write Confinement | Secret Read Masking (`secrets.json`) |
| --- | --- | --- | --- | --- | --- |
| **`bwrap`** (implemented, ready when installed) | Bubblewrap `--ro-bind / /` + `--tmpfs /tmp` + `--bind <clone>` | Yes (`bwrap` + userns) | — (not installed) | `EROFS` on host; ephemeral `/tmp` | Yes (`--ro-bind /dev/null`) |
| **`layered`** *(preferred when userns works)* | `unshare -Urm` + `pivot_root` (read-only `--rbind`, private `/tmp` tmpfs) **+** inner **Landlock LSM** (`lib/landlock-exec.py`) | Userns only (no `bwrap`, no root) | **83.9 ms** median / **87.8 ms** p95 | `EROFS` on parent + `EACCES` even on `/tmp` | Yes (`mount --bind /dev/null`) |
| **`landlock`** *(universal Linux ≥ 5.13 fallback)* | Kernel Landlock LSM (`landlock_create_ruleset` / `add_rule` / `restrict_self` + `PR_SET_NO_NEW_PRIVS`) via 140-line stdlib Python wrapper | **No** (works without `bwrap`, userns, or root) | **19.7 ms** median / **20.3 ms** p95 | `EACCES` / `EXDEV` everywhere outside `cloneDir`, `scratchDir`, `/dev/null` | No (Landlock write-only ruleset leaves global reads open) |
| **`unshare`** | `unshare -Urm` + `pivot_root` with RO `--rbind` + private `/tmp` tmpfs | Userns only (no `bwrap`, no root) | **64.3 ms** median / **68.3 ms** p95 | `EROFS` on parent; host `/tmp` untouched (private tmpfs) | Yes (`mount --bind /dev/null`) |

**Landlock implementation gotchas verified empirically:**
- Non-directory allowlist entries like `/dev/null` fail with `EINVAL` if given directory-only flags (`MAKE_*`, `REMOVE_*`, `REFER`). `lib/landlock-exec.py` splits directory vs file masks (`WRITE_FILE | TRUNCATE` for files).
- `LANDLOCK_ACCESS_FS_REFER` (ABI ≥ 2, Linux 5.19+) is required to allow in-clone renames/hardlinks while denying cross-boundary renames/hardlinks (`EXDEV`) into the parent repo.
- `LANDLOCK_ACCESS_FS_TRUNCATE` (ABI ≥ 3, Linux 6.2+) is required to block `truncate(2)` / `ftruncate(2)` overwrites of existing parent files (`EACCES`).
- On `git clone --shared`, `.git/objects/info/alternates` points to the parent repo's `.git/objects`. Because the parent repo stays **read-only** in all backends, `git log` / `git diff` / `git commit` in the clone read shared parent packfiles cleanly while any write into `parent/.git` fails with `EACCES`/`EROFS`.

### macOS Seatbelt (`sandbox-exec`) Profile Plan

Implemented in `lib/sandbox-macos.mjs` for parity with Claude Code's macOS sandbox (`@anthropic-ai/sandbox-runtime`):

- Starts from `(version 1)` + `(allow default)` so macOS dyld, Mach IPC, and read-only system toolchains run cleanly.
- Globally enforces `(deny file-write*)` (covering create, write, unlink, rename, hardlink, truncate, chmod, and xattrs).
- Narrowly re-allows `(allow file-write* ...)` **only** for `realpath(cloneDir)`, `realpath(scratchDir)`, and `/dev/null`, `/dev/zero`, `/dev/dtracehelper`, `/dev/tty*`.
- Explicitly adds `(deny file-read* (subpath "<secretsPath>"))` for `~/.codecanvas/secrets.json`.
- Escapes SBPL string literals and rejects control characters/newlines in paths to prevent profile injection.
- **Note:** `sandbox-exec` is marked deprecated by Apple since macOS 10.12 but remains active on macOS 14–16 and is the mechanism Claude Code itself uses on macOS. Because this VM is Linux, live macOS adversarial execution of `node run.mjs` is gated as a CI check in WP5.3.

## 3. Headless `claude` CLI Contract & `PreToolUse` Hook

### Real CLI Invocation Contract (`lib/runner.mjs`)

```bash
claude -p "<task.request>" \
  --output-format stream-json \
  --verbose \
  --no-session-persistence \
  --settings "<scratchDir>/claude-settings.json" \
  --mcp-config "<scratchDir>/mcp.json" \
  --strict-mcp-config \
  --permission-mode acceptEdits \
  --allowedTools "Read,Edit,Write,Glob,Grep,Bash,mcp__canvas__*"
```

Key contract details verified:
- **`--output-format stream-json` requires `--verbose`** in Claude Code CLI; emits NDJSON lines (`system:init`, `assistant` text/`tool_use`, `user` `tool_result`, `result`).
- **Zero repo footprint (I1):** Ephemeral `claude-settings.json` (containing both `sandbox` settings and `hooks.PreToolUse`) is written to the agent's private `scratchDir` (`~/.codecanvas/agents/<repoId>/<task>-scratch/`), never into `.claude/` inside the repo.
- **Process-group supervision:** Spawned `detached: true`; timeout/abort/exit terminates the entire process group via `process.kill(-pid, 'SIGTERM')` → `SIGKILL` (never broad `pkill -f`).
- **Real `claude` auth/state note for WP5.3:** When wrapping the real `claude` binary inside the daemon's OS sandbox, `claude` requires read access to OAuth credentials/settings and HTTPS egress to `api.anthropic.com`. Isolating `CLAUDE_CONFIG_DIR` to a scratch copy (or allowlisting only `~/.claude/projects` / `~/.claude/debug` while keeping `~/.claude/settings.json` and the parent repo read-only) prevents the agent from mutating the user's global Claude config.

### `PreToolUse` Hook Defense-in-Depth (`lib/pretooluse-hook.mjs`)

- Implements the exact Claude Code stdin/stdout JSON hook protocol (`hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "allow" | "deny", permissionDecisionReason }`).
- Resolves every `Write` / `Edit` / `MultiEdit` / `NotebookEdit` target with **ancestor-walking `fs.realpathSync()`**, defeating both `../` traversal and symlinks inside the clone pointing outside — **even when the target file does not exist yet** (`clone/link-to-parent/new-file.txt`).
- Blocks direct `Write`/`Edit` into `<cloneRoot>/.git/**` (preventing `.git/config`, `.git/hooks/*`, or `.git/objects/info/alternates` poisoning).
- Provides fast static Bash denials for `core.hooksPath`, `GIT_DIR`/`GIT_WORK_TREE`/`GIT_COMMON_DIR` outside the clone, and `git -C` outside the clone (while relying on the **OS sandbox** as the true enforcement boundary for Bash).
- **Fail-closed:** denies if `CODECANVAS_CLONE_ROOT` is missing or unresolvable.
