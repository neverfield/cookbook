## 1. Question

Can codecanvas spin up an isolated agent clone (`git clone --shared`), apply the active change set patch, install isolated dependencies from a warm package-manager store (without symlinking parent `node_modules`), safely copy `.env*` files, and boot an isolated Next.js Turbopack agent host with correct workspace root resolution within the **≤ 90 s** warm-store budget (`ARCHITECTURE-V2` §8.3, §18)?

Sub-questions tested:
1. How do `git clone --shared`, `git worktree`, and full `git clone --no-hardlinks` compare on setup time, incremental disk footprint, and `.git` isolation?
2. How fast and disk-efficient is `pnpm install --frozen-lockfile --prefer-offline` (and `--offline`) on a warm store compared to `cp -al` hardlink copy and symlinked `node_modules`, and which strategies preserve true isolation?
3. Can `.env*` files be copied safely (rejecting symlinks/path traversal, preserving `0600` permissions, keeping `git status` clean) and loaded by the Next.js agent host?
4. How does Next.js Turbopack resolve workspace roots when a shared clone lives nested under `<parent>/.codecanvas/cache/clones/` vs externally at `~/.codecanvas/agents/<repoId>/<task>/`, with and without explicit `turbopack.root`?
5. What is end-to-end cold and warm agent-host startup latency on both native (8 vCPU) and reference-box-equivalent (4 vCPU via `taskset -c 0-3`) hardware?

## 3. Measured Results

### Experiment A: Clone Creation & Disk Footprint (`3 trials`)

Parent fixture before clone: `.git` = `3.89 MB` disk (`3.75 MB` apparent); full repo incl. `node_modules` = `616.64 MB` disk (`554.77 MB` apparent).

| Strategy | Median Time | Min / Max | Clone `.git` Disk | Incremental Disk vs Parent | Own `.git` Dir? | Isolation Assessment |
| --- | ---: | ---: | ---: | ---: | :---: | --- |
| `git clone --shared` (external) | **9.4 ms** | 9.2 / 11.6 ms | 0.18 MB | **0.54 MB** | Yes | Full `.git` isolation (`alternates` reads parent objects); `git apply` patch took **2.2 ms** with parent `git status` clean |
| `git clone --shared` (nested in `.codecanvas/cache/clones/`) | **9.1 ms** | — | 0.18 MB | **0.54 MB** | Yes | Parent `git status` remains clean (`.codecanvas/.gitignore` ignores `cache/`) |
| `git worktree add --detach` | **7.9 ms** | 7.9 / 8.1 ms | pointer file | 0.36 MB | **No** | **Rejected:** `.git` is a file pointing to `<parent>/.git/worktrees/...`; agent git config/hook/ref mutations can affect parent repo |
| `git clone --no-hardlinks` (full clone) | **13.6 ms** | — | 3.90 MB | 4.26 MB | Yes | Copies entire `.git/objects` pack (7.9× larger incremental disk on this fixture; scales linearly with multi-hundred-MB real histories) |

**Alternates caveat:** `git clone --shared` writes `<parent>/.git/objects` into `.git/objects/info/alternates`. Commits created inside the clone write new objects into the clone's own `.git/objects`, and `HEAD` stays reachable in parent. Parent `git gc --prune=now` could only prune objects that became unreachable in parent after the clone was created; because agent clones are short-lived per-task sandboxes deleted on accept/reject, this is safe in normal workflows.

### Experiment B: Dependency Install Strategies (Warm Store, `3 trials`)

| Strategy | Command / Method | Median Time | Min / Max | Clone Apparent Size | Incremental Disk vs Parent | Workspace `@fixture/ui` Isolated? | Safe for Agent Clones? |
| --- | --- | ---: | ---: | ---: | ---: | :---: | :---: |
| **pnpm prefer-offline (Recommended)** | `pnpm install --frozen-lockfile --prefer-offline` | **837.5 ms** | 826.3 / 863.7 ms | 551.05 MB | **9.02 MB** | **Yes** | **Yes** |
| pnpm offline | `pnpm install --frozen-lockfile --offline` | **831.0 ms** | 830.3 / 850.9 ms | 551.04 MB | **9.02 MB** | **Yes** | **Yes** (fails if a lockfile entry is missing from store) |
| pnpm offline + ignore-scripts | `pnpm install --frozen-lockfile --offline --ignore-scripts` | **842.9 ms** | 812.1 / 870.8 ms | 551.05 MB | **9.05 MB** | **Yes** | Risky if repo requires `prisma generate` / native postinstall |
| Hardlink copy (`cp -al`) | `cp -al <parent>/**/node_modules` | 244.1 ms | — | 551 MB | ~9 MB | Needs re-link | **No:** `sharesInodeWithParent = true` (ext4 has no CoW reflink); in-place writes corrupt parent `node_modules` |
| Symlink `node_modules` | `ln -s <parent>/node_modules` | 0.35 ms | — | 0 MB | 0 MB | **No (escaped!)** | **No:** `realpath(@fixture/ui)` resolves to `<parent>/packages/ui`; mutating deps mutates parent |

**Key finding:** Because pnpm hardlinks immutable package files from the global content-addressable store (`~/.local/share/pnpm/store/v10`) into a freshly created `node_modules` tree with clone-local workspace symlinks, `pnpm install --frozen-lockfile --prefer-offline` achieves **sub-second warm install (0.84 s)** and only **9.02 MB incremental disk** (1.6% of apparent `551 MB`) while preserving full directory and workspace isolation.

### Experiment D: Next.js Turbopack Root Resolution

Tested four configurations against sentinel values mutated strictly in the clone (`packages/ui/src/Sentinel.tsx`, `packages/shared/src/catalog.ts`, `apps/web/src/lib/marker.ts`) vs `'PARENT_ORIGIN'` in the parent repo:

| Case | Clone Location | `turbopack.root` Set? | Ready Time | Sentinels Resolved From | Multi-Lockfile / Root Warnings | Cross-Contamination / Notes |
| --- | --- | :---: | ---: | --- | :---: | --- |
| **D1a** | Nested (`<parent>/.codecanvas/cache/clones/d1a-naive`) | No | 351.0 ms | Clone (`NESTED_NAIVE`) | **1 warning** (see below) | Next.js 16 stopped at clone's `.git` boundary, so modules did not escape, **but emitted a workspace-root warning** |
| **D1b** | Nested (`<parent>/.codecanvas/cache/clones/d1b-explicit`) | **Yes (`cloneRoot`)** | 354.0 ms | Clone (`NESTED_EXPLICIT`) | **0 warnings** | Editing clone `@fixture/ui` HMR-updated in **288.3 ms**; temporarily editing parent `@fixture/ui` caused **0 leakage** into clone |
| **D2a** | External (`~/.codecanvas/agents/reelhouse/d2-external`) | No | 347.1 ms | Clone (`EXTERNAL_CLONE`) | **0 warnings** | Clean resolution with no ancestor lockfile |
| **D2b** | External (`~/.codecanvas/agents/reelhouse/d2-external`) | **Yes (`cloneRoot`)** | 349.5 ms | Clone (`EXTERNAL_CLONE`) | **0 warnings** | Recommended belt-and-suspenders configuration |
| **D3** | Concurrent parent (`:4720`) + external clone (`:4721`) | Yes | — | Parent=`PARENT_ORIGIN`, Clone=`EXTERNAL_CLONE` | **0 warnings** | Zero lockfile/`.next/dev/lock` collision (clone uses `distDir: '.codecanvas/cache/next'`) |

**Exact verbatim warning emitted in D1a (nested clone without explicit `turbopack.root`):**

```text
⚠ Warning: Next.js ignored pnpm-workspace.yaml in /tmp/codecanvas-s5-S86sgO/reelhouse-fixture because it is outside the current Git repository (/tmp/codecanvas-s5-S86sgO/reelhouse-fixture/.codecanvas/cache/clones/d1a-naive).
 To use this directory, set `turbopack.root` in your Next.js config.
```

**Architectural implication:**
1. Next.js 16's `.git`-boundary guard prevented root escape in D1a *only* because `git clone --shared` created an independent `.git` directory. Older Next.js 15 releases or worktree layouts without an isolated `.git` directory do not have this safeguard.
2. Keeping agent clones **outside** the parent repo at `~/.codecanvas/agents/<repoId>/<task>/` (§8.3) eliminates ancestor lockfile discovery completely, **and** having codecanvas's Next.js launch preload (§3.4) unconditionally set `turbopack.root = <cloneWorkspaceRoot>` and `distDir = '.codecanvas/cache/next'` guarantees zero warnings and zero parent-root escape in both external and nested layouts across Next 15 and 16.

## 4. Scaling Extrapolation to Large Production Monorepos (Reelhouse-Scale)

Our synthetic fixture (~312 locked packages, 551 MB apparent `node_modules`, 8 routes) finishes cold startup in **3.73 s** on 4 vCPUs. Scaling honestly to a large production Next.js monorepo (e.g., 1,500–2,500 locked packages, 1.5–2.5 GB apparent `node_modules`, heavier component trees, and 500 MB `.git` pack):

- `git clone --shared`: stays **< 0.5 s** (does not copy `.git/objects`, only checks out working tree).
- `pnpm install --frozen-lockfile --prefer-offline` (warm store): scales roughly linearly with file count in `node_modules`, typically **8–25 s** on SSD/NVMe with 4 vCPUs.
- Safe `.env*` copy: **< 0.05 s**.
- `next dev --turbopack` `Ready` + first route compile: typically **4–15 s**.
- **Projected large-monorepo cold total:** **~13–41 s**, well inside the **≤ 90 s** budget.
- **Caveat for npm / Yarn Classic repos:** Projects using `npm ci --prefer-offline` (which extracts tarballs rather than hardlinking from a CAS store) will incur higher install time (~20–55 s on large repos) and full `node_modules` disk duplication. Projects with heavy launch-recipe `pre` commands (e.g., Prisma/GraphQL codegen) should copy pre-generated build outputs listed in the launch recipe rather than re-running full codegen on every clone unless schema files changed.
