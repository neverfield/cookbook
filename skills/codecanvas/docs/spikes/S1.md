**Date:** 2026-11-27  
**Status:** Complete

**Harness:** `skills/codecanvas/e2e/spikes/s1-preload/` (`node run.mjs`)

## 1. Question

From `ARCHITECTURE-V2` (§3.1, §3.4, §4.1, §18):

> Can codecanvas instrument a project by running the project's **own dev script** (`npm run dev` / `pnpm --filter <app> dev` / wrapper scripts) via `NODE_OPTIONS=--import=...` without editing any app source, config, or `package.json`, leaving `git status` 100% clean outside `.codecanvas/` (`I1`)?

Specifically, S1 verifies:
1. **Next.js 15 & 16 (Turbopack and Webpack):** In-memory config wrapping (`.ts`, async `.mjs`, and no-config), private `distDir` (coexisting alongside a developer's own `next dev` holding `.next/dev/lock`), private `typescript.tsconfigPath`, suppressing `next-env.d.ts` (and any other repo) mutations, runtime copy under `.codecanvas/cache/runtime/<version>/`, workspace package instrumentation outside the app root (`transpilePackages` + `turbopack.root`), and Edge-safe `__cc` inline prelude.
2. **Vite 5–8:** Zero-edit config wrapping via `--import` + `module.register` hooks (plain object, async function, and zero-config), private `cacheDir` (coexisting alongside a developer's own `vite`), `css.devSourcemap: true`, workspace package transformation, and clean `git status`.
3. **Activation, handshake, and orchestrators:** Preload activates only in target framework dev processes inside the app/workspace root (skipping `pnpm`, wrapper scripts, and helper Node subprocesses), sends an authenticated loopback handshake to the daemon, and fails loudly on handshake timeout when a root orchestrator (e.g. `turbo dev` strict env mode) strips `NODE_OPTIONS`.

## 2. What Was Tried

A self-contained harness (`skills/codecanvas/e2e/spikes/s1-preload/`) was built and executed against freshly created, git-initialized `pnpm` monorepo fixtures (`apps/web` + external workspace package `packages/ui` `@acme/ui`):

- **Entry preload (`preload.mjs`):** Loaded via `NODE_OPTIONS="--import=file:///.../preload.mjs"` (preserving any existing `NODE_OPTIONS`). Runs a synchronous activation check inspecting `CC_TARGET_FRAMEWORK`, `CC_APP_ROOT`, `CC_WORKSPACE_ROOT`, `process.cwd()`, and `process.argv[1]` (with `realpath`). Non-target Node processes (`pnpm`, dotenv-style `scripts/dev-wrapper.mjs`, `node -e` preflight checks, Turbopack loader workers) exit the preload immediately without registering hooks or opening sockets.
- **Next.js 15 (`15.5.29`) & Next.js 16 (`16.4.6`) instrumentation (`Module._load` proxy):**
  - Because Next.js CJS modules define exports with `Object.defineProperty(exports, name, { enumerable: true, get })` (`configurable: false`), `Module._load` returns a `Proxy` over the original exports object instead of mutating properties directly.
  - Wraps `next/dist/server/config.js` (`default` export `loadConfig`) for `phase-development-server` (non-`rawConfig` calls) to inject:
    - Private `distDir`: `.codecanvas/cache/next` on Next 15; `distDirRoot = '.codecanvas/cache/next'` and `distDir = '.codecanvas/cache/next/dev'` on Next 16 (matching Next 16's `distDirRoot` + `/dev` split).
    - Private `typescript.tsconfigPath`: `.codecanvas/cache/tsconfig.json` (generated at launch extending `../../tsconfig.json`).
    - `allowedDevOrigins`: merges `['127.0.0.1', 'localhost', '*.localhost']`.
    - `transpilePackages`: merges workspace packages (`['@acme/ui']`).
    - `experimental.serverComponentsHmrCache = false`.
    - `turbopack.root = workspaceRoot` and `outputFileTracingRoot = workspaceRoot` (when monorepo root differs from app root), plus `turbopack.rules['*.tsx' | '*.jsx']` pointing to `./.codecanvas/cache/runtime/<version>/next-loader.cjs`.
    - `webpack` wrapper prepending an `enforce: 'pre'` rule on `/\.[jt]sx$/` while preserving any user `webpack(config, ctx)` hook.
  - Wraps `next/dist/lib/typescript/writeAppTypeDeclarations.js` to redirect `next-env.d.ts` writes from `<appRoot>` into `.codecanvas/cache/next-env.d.ts`.
  - Wraps `next/dist/lib/typescript/writeConfigurationDefaults.js` as a defense-in-depth guard against writes to `<appRoot>/tsconfig.json`.
  - Wraps `next/dist/server/lib/generate-agent-files.js` (discovered during testing on Next 16.4.6; see §4.1) to suppress automatic creation/mutation/deletion of `<appRoot>/AGENTS.md`.
  - Sends an authenticated `POST /handshake` (`Authorization: Bearer <token>`) to the loopback daemon reporting `{ framework, version, pid, ppid, bundler, appRoot, workspaceRoot, distDir, tsconfigPath, transpilePackages, turbopackRoot }`.
- **Vite 5 (`5.4.21`), 6 (`6.4.6`), 7 (`7.3.8`), 8 (`8.4.0`) instrumentation (`module.register` + `hooks.mjs`):**
  - Primary hook intercepts Vite's bundled temp config module — both Vite 5's `<root>/vite.config.*.timestamp-*.mjs` and Vite 6–8's `node_modules/.vite-temp/vite.config.*.timestamp-*.mjs` (plus direct `vite.config.(mjs|js|ts|mts)` for `--configLoader native`).
  - Rather than regex-rewriting esbuild/Rolldown output (which varies between `export default ...` and `export { x as default }`), `hooks.mjs` returns a 3-line ESM re-export wrapper that imports `<url>?__cc_orig=1` (served from disk by `load()`) and wraps its default export (plain object, sync function, or async function) with `injectCodecanvasIntoViteConfig(...)`.
  - Fallback hook wraps `vite/dist/node/cli.js`'s `createServer({...})` call when no ESM/TS `vite.config.*` exists (handling zero-config and CJS-config Vite apps cleanly without double-registering plugins).
  - The injected `codecanvas:instrument` plugin (`enforce: 'pre'`, `apply: 'serve'`) sets `cacheDir` to `.codecanvas/cache/vite`, `css.devSourcemap: true`, adds `workspaceRoot` to `server.fs.allow`, instruments workspace `.tsx`/`.jsx` files before `@vitejs/plugin-react`, and sends the daemon handshake in `configResolved`.
- **Directive-preserving, Edge-safe `__cc` prelude (`runtime/transform.cjs`):**
  - Zero external npm dependencies (copied into `.codecanvas/cache/runtime/<version>/` in ~0.5 ms).
  - Scans past leading comments and `'use client'` / `'use server'` / `'use cache'` directives before inserting `const __ccNoop = ...; const __cc = (typeof globalThis !== "undefined" && globalThis.__cc) || __ccNoop; __cc.mod(...);`.
  - Tested on RSC (`app/page.tsx`), `'use client'` components (`Counter.tsx`, `@acme/ui` `Button.tsx`), and an Edge Runtime route (`app/api/edge/route.ts` with `export const runtime = 'edge'`).

## 4. Concrete Surprises & Engineering Constraints Discovered

1. **Next 16.3+ auto-writes `AGENTS.md` when launched by an AI coding agent (`I1` blocker if unhandled):**  
   Next.js `16.3.0+` (`16.4.6` tested) detects AI coding agents (Claude Code, Cursor, etc.) during `next dev` and creates or mutates `<appRoot>/AGENTS.md` via `next/dist/server/lib/generate-agent-files.js`. Crucially, setting `config.agentRules = false` is **unsafe** in `16.4.0+` because Next explicitly *removes* an existing managed block from tracked `AGENTS.md` when `agentRules: false`. The preload MUST intercept `next/dist/server/lib/generate-agent-files.js` and no-op `writeAgentFiles`, `writeAgentFeedbackFiles`, `removeAgentRulesFiles`, and `removeAgentFeedbackFiles`. Verified on both repos without `AGENTS.md` (not created) and repos with pre-existing `AGENTS.md` (untouched).
2. **Next 16 `distDirRoot` vs `distDir`:**  
   Next 16's `assignDefaultsAndValidate` saves `result.distDirRoot = result.distDir` and rewrites `result.distDir = path.join(result.distDir, 'dev')` during `PHASE_DEVELOPMENT_SERVER`. Wrapping `loadConfig` after it returns MUST set both `config.distDirRoot = '.codecanvas/cache/next'` and `config.distDir = '.codecanvas/cache/next/dev'` when `'distDirRoot' in config` (Next 16), and `config.distDir = '.codecanvas/cache/next'` on Next 15.
3. **Non-configurable CJS getter exports in Next.js:**  
   Next compiles its CJS internals (`config.js`, `writeAppTypeDeclarations.js`, `writeConfigurationDefaults.js`, `generate-agent-files.js`) using non-configurable `Object.defineProperty` getters. `Module._load` must return a `Proxy` (or cloned export namespace) rather than mutating `exports.default` directly.
4. **Process-group teardown race on Next Turbopack:**  
   Sending `SIGTERM` to `-pgid` and waiting only on the parent `pnpm` process's `'exit'` event races with Next's forked `start-server.js` flushing trace/build files into `.codecanvas/cache/next` during shutdown. Waiting until `process.kill(-pgid, 0)` returns `ESRCH` (with `SIGKILL` escalation) eliminates post-teardown file recreation.
5. **Next 15 `NODE_OPTIONS` repeated-flag caveat:**  
   In `next@15.5.29` (`next/dist/server/lib/utils.js`), `formatNodeOptions` assumes each flag in `NODE_OPTIONS` has a string value (unlike Next 16, which handles `Array.isArray(value)`). If a user's environment already contains `--import=...` when launching Next 15, the launcher should chain both imports via a single generated bootstrap file or warn, rather than appending a second `--import=...` flag.
6. **Zero-config Vite apps need a `cli.js` fallback:**  
   Vite only emits a temp config module (`node_modules/.vite-temp/...` or `vite.config.*.timestamp-*.mjs`) when a config file exists. Pairing the primary temp-config load hook with a deduplicated `vite/dist/node/cli.js` `createServer(inlineConfig)` fallback covers zero-config and CJS-config Vite apps across Vite 5–8.
7. **Pinned OSS set boundary:**  
   The 5 pinned public OSS repositories are introduced in WP2.1 (not yet present in Sprint 0 greenfield). S1 validated the full set of representative OSS patterns locally (pnpm monorepo with external TSX workspace package, `.ts` / async `.mjs` / zero-config, dotenv/preflight wrapper scripts, Edge runtime routes, pre-existing tracked `next-env.d.ts`/`tsconfig.json`/`AGENTS.md`, concurrent developer dev servers, and strict-env orchestrator failure). Running the production preload adapter against the 5 pinned OSS repos remains a required WP2.1/WP2.4 acceptance check.

## 5. Verdict: GO

**GO** on launch-time preload instrumentation via the app's own dev script for both **Next.js 15/16 (Turbopack & Webpack)** and **Vite 5–8**.

- All 15 spike scenarios pass with **100% clean `git status`** (`I1`), working workspace-package instrumentation (`@acme/ui`), Edge-runtime safety (`__cc` prelude), side-by-side coexistence with the developer's own dev server, accurate activation filtering, and fail-loudly handshake enforcement.
- Overhead is negligible on Next.js (-8.6% to +14.7% cold boot; +71 ms / +3.1% on Next 16 Turbopack; ~0.5 ms runtime copy) and modest on Vite (+57 to +123 ms cold boot on a ~625 ms server).
- No fallback to degraded generic-proxy mode or one-line opt-in is needed for Next 15/16 or Vite 5–8.
